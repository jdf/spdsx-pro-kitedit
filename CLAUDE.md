# spdsx-patchedit — orientation for Claude

Interactive kit designer for the Roland SPD-SX PRO. C++20, JUCE 8, CMake +
vcpkg. Public repo: github.com/jdf/spdsx-pro-kitedit (note: repo name differs
from this directory). Push with jdf's `jj push-main` alias.

## Conventions (STRICT — jdf cares)
- **Google C++ style throughout**: `.cc`/`.h` files, `#ifndef SPDSX_PATCHEDIT_SOURCE_<FILE>_H_` guards (never `#pragma once`), UpperCamelCase methods (trivial accessors like `name()`/`set_name()` may be snake_case), `kUpperCamelCase` enumerators/constants, `snake_case_` data members. JUCE overrides keep their inherited names.
- **The tree is clang-format clean — just run it** (`clang-format -i <files>`; it is also VS Code's formatter for C++ via clangd). `.clang-format` is authoritative and agrees with the code: braces attach to the opening line (`void Foo() {`), a file's own header includes first, then std, then other libraries, then project headers. This was NOT true before 2026-07-14 — the config and the code disagreed and formatting a file rewrote it wholesale — so ignore any older note telling you to hand-match the surrounding style.
- **JUCE string gotcha**: `juce::String` from a `char*` literal reads it byte-per-character — any non-ASCII UTF-8 (…, ·, —) becomes mojibake. Wrap such literals in `juce::String::fromUTF8(...)`, always.
- **jj (not git) for VCS**, colocated. Commit liberally in small semantic chunks (one logical change per commit, each builds and works; `jj commit <paths>` for per-file chunks). **Never push, and don't offer to** — jdf runs `jj push-main` himself when he wants. Co-author trailer: `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- Also honored in sibling repos: `github.com/jdf/specgram` (the spectrogram lib, dir `../specgram`) and `github.com/jdf/spdsx-py` (`../spdsx-py`, the protocol RE).

## Build / run
```
cmake --preset default && cmake --build --preset default
"./build/spdsx-patchedit_artefacts/RelWithDebInfo/SPD-SX PROgram.app/Contents/MacOS/SPD-SX PROgram"
```
`./install-app.sh` builds and installs `/Applications/SPD-SX PROgram.app` (the product renamed from spdsx-patchedit 2026-07-25; CMake target and BUNDLE_ID keep the old name) — a normal double-clickable app with its own icon (`assets/icon.svg` → `icon.png` → JUCE `ICON_BIG`; regen recipe in `assets/README.md`) and the `.spdsx` extension registered, so double-clicking a document opens it (single-instance; `App::anotherInstanceStarted` → `MainComponent::OpenDocument`).
Targets: the GUI app; `spdutil` (device CLI: read `ping`/`info`/`dump`/`kits`/`kit <N>`/`samples`/`readwave`; write `assign`/`setname`/`setparams`/`sendwave` (upload+register)/`deletewave`/`padlink` (write ops take `--commit`) — run it bare for the options); `spdsx_device` (JUCE-free static lib). Preset is RelWithDebInfo (breakpoints). VS Code: open `../hax.code-workspace` (multi-root); `--load <slot> <wav>` pre-fills slots for testing.

## Architecture (source/)
- `kit_model.{h}` — the **active kit**: name + 17 `Pad`s — the KitModel "objects": pads 0-8, then the eight external trigger inputs as objects 9-16 (triggers are structurally pads on the device; `IsTrigger`/`TriggerObject`/`TriggerOf` map between numberings). A layer holds a `LayerSample` — **dual identity**: a local audio file OR a device pool wave (`device_index` > 0; metadata-only until sample transfer is cracked, so it displays but can't play; at sync time local files get uploaded and become indices too). Each pad also carries a `PadParams` (layer mode, fade point/end — end constrained >= point, defaults 80/127 matching the device factory — dynamics on/off, dynamics curve, fixed velocity — the strike level every hit plays at when dynamics is off — trigger reserve, which is read/write only, not emulated, and the HI-HAT closed-pedal trio hi_hat_volume/hi_hat_fade_in/hi_hat_decay, of which only volume is emulated — it scales the closed layer in TriggerPad; fade in/decay await engine envelopes). `PadParams` mutates as a unit: one setter, one action, one listener event. Observable (`KitModel::Listener`). UI/engine/document all react to it.
- `device_model.h` — the **whole-device mirror**: 200 `KitData` (name + pads) as plain data, plus which kit is active, plus the **sample pool** (`sample_pool()`/`FindSample(index)` — the device's wave directory as `device::SampleRecord`s, metadata only). Not observable; the active kit is edited through KitModel and stashed back by the document.
- `layers.{h,cc}` — JUCE-free pure logic emulating the device's 8 layer types (MIX/FADE1/FADE2/XFADE/SWITCH/SW(MONO)/ALTERNATE/HI-HAT): `ComputeLayerWeights(...)` -> per-layer selection weights (0..1) + choke flag, deliberately excluding loudness; `DynamicsGain(curve, velocity)` -> loudness through the Dynamics Curve (LINEAR/LOUD1/LOUD2/LOUD3 — power-curve approximations, real device shapes unpublished). Selection always follows real strike velocity; loudness is weights × DynamicsGain (with Dynamics off, × the linear gain at the pad's fixed velocity). Mode/curve names are shared by the UI and the JSON persistence.
- `actions.h` — `SetSampleAction`, `SetPadParamsAction` (undoable). `main_component` wraps edits in `undo_` transactions (Load, MoveSample, MovePad, pad-param changes).
- `device_db.{h,cc}` — the persistence store: a single `*.spdsx` **SQLite** file (via vcpkg `unofficial-sqlite3`). Schema: `meta` (schema_version/app/created), `kits`+`pads` each carrying a `snapshot` column (`current` = the working doc, `base` = the last-synced state for 3-way sync; pads rows 9-16 are the triggers, since v5), and `samples` (pool directory metadata + cached audio as a BLOB). `DeviceDb` reads/writes a `DeviceModel` (`ReadKits`/`WriteKits` per snapshot, `WritePool`, `HasAudio`/`GetAudio`/`PutAudio`, `CaptureBase`). Covered by `device_db_test.cc`.
- `device_sync.{h,cc}` — the **three-way sync engine**, pure logic (no I/O): `MergePad` does a FIELD-wise current/base/theirs merge (a field changed on one side takes that side; changed apart = conflict, resolved per pad by `SyncResolution` mine/theirs/skip — skip leaves the pad AND its base untouched so it re-flags next sync); `FindKitConflicts` renders dialog-ready descriptions with both values; `PlanKitSync` yields a `KitSyncPlan` (new_current/new_base + which name/params/waves need device writes — a theirs-wins conflict needs NO write, it pulls); `PlanUploads`/`SubstituteUploads` assign free pool indices (`NextFreeSampleIndex`) to distinct local files in written layers and swap them to `DeviceWave` in both snapshots; `BuildKitWrite` lowers a plan to wire-level `KitWrite`s; `ExecutePush(dev, uploads, kits, on_uploaded, pace, commit_timeout)` drives UploadWave (each durable, fires on_uploaded) then name/wave/param writes then ONE `Commit`. Also home of `KitDataFromDevice` (shared with Load Device State) and `DeviceParamsFromPad`. Fully covered in `device_sync_test.cc`, including pushes against the fake port and an end-to-end plan→wire test.
- `sample_upload.{h,cc}` — `SmpFromAudioFile`: decode any JUCE-readable file, resample to 48 kHz (Lagrange, the only rate the device plays), first two channels, 16-bit, wrap via `PcmToRfwv` (checksum included). Refuses non-audio/empty/absurdly-long input with a message.
- `disclaimer_dialog.{h,cc}` — the first-launch clickwrap (as-is / reverse-engineered-protocol risk acknowledgment): Accept records `disclaimerAcceptedVersion` in settings (bump `kDisclaimerVersion` when the text materially changes — everyone re-accepts); Quit/escape/close = decline via the destructor, and `MainComponent::MaybeShowDisclaimer`'s callback quits the app. Selftests skip it (`main.cc` gates on SPDSX_SELFTEST). Pure view.
- `about_dialog.{h,cc}` — the application menu's About box: embedded icon (`juce_add_binary_data` of assets/icon.png), name, version (the one `SPDSX_VERSION` define from `project(VERSION)`, also behind `getApplicationVersion` and `spdutil --version`), a source-code link, per-dependency credit rows (hyperlink + license) for the headline deps, and an "Open Source Licenses" button opening `Contents/Resources/LICENSES.txt`. Pure view. **That file is built by `collect-licenses.py`** (repo root): our LICENSE + every vcpkg `share/*/copyright` (minus gtest/gperf/vcpkg-* which don't ship) + `licenses/*.txt` (the full AGPLv3, which JUCE's copyright only links) + JUCE's own vendored LICENSE/COPYING files (harfbuzz, sheenbidi, pnglib, zlib, oggvorbis… — its vcpkg copyright covers only JUCE itself). Wired as a generated bundle resource (`MACOSX_PACKAGE_LOCATION Resources` + `add_custom_command` DEPENDS), NOT a POST_BUILD step, so it regenerates when the collector/LICENSE/version change rather than only on relink.
- `sync_dialog.{h,cc}` — `SyncConflictPanel`: the conflict-resolution dialog (async modal `DialogWindow`). One row per conflicted pad/kit-name, each a CHECKBOX + description + the outcome in words; a `TriStateToggle` "Select all" (a ToggleButton subclass painting a dash for the mixed state, since JUCE has none) and three bulk buttons — Keep Mine / Keep Device's / Do Nothing — set the resolution of every ticked row at once, because a sync that conflicts on one pad usually conflicts on many. Rows start ticked and resolved to MINE (the user pressed Sync). Sync/Cancel buttons; any other close path (escape, close button) reports cancel via the destructor. Pure view; `on_apply` still hands back one `SyncResolution` per conflict in order.
- `device_document.{h,cc}` — `DeviceDocument : FileBasedDocument`, bridging the in-memory model to `DeviceDb`. The document is a single SQLite FILE `*.spdsx` (no more folder-package/UTI/PLIST — `existsAsFile()` just works). `loadDocument`/`saveDocument`/`Autosave`/`CreateNew`/`OpenDevice` all go through `db_`; `SwitchKit` stashes the active kit, loads the next, preserves the unsaved flag (view state, not an edit). Undo histories are PER-KIT (`MainComponent::undo()` returns the current kit's lazily-created UndoManager) and survive switches; document-level events (open/new/import) clear all via `on_history_reset`, and `on_model_reload` brackets `LoadActiveKitIntoModel` so a load's change-listener storm isn't mistaken for a user edit. `ImportKitFile` still reads legacy single-kit `.kit` v1-v4 into the active kit (File > Import Kit…). Cached wave audio lives as DB blobs: `StoreWaveAudio` (from a download), `HasCachedAudio`, and `CachedWaveFile` (extract-on-demand to a temp file the engine can load). `ReplaceWithDeviceState` (Load Device State) writes kits+pool AND `CaptureBase()` (device == current == base). **NO EXPLICIT SAVE — everything autosaves** (`Autosave()` = `db_->WriteKits` after a 1s quiet period; quit flushes). Startup opens the last file or creates `~/Documents/SPD-SX PRO.spdsx`; `CreateNew` blows away anything (incl. a legacy folder) at that path. All prior-document JSON read paths were dropped (jdf approved; old folder docs won't open). NOTE: FileBasedDocument's sync save/load are compiled out in JUCE 8, so the app drives loadDocument/saveDocument through OpenDevice/CreateNew/Autosave; `device_document_test.cc` reaches the protected ones with a `using`-subclass. Covered by that suite.
- `knob_look_and_feel.{h,cc}` — `KnobLookAndFeel : LookAndFeel_V4`: every rotary slider renders as the skeuomorphic bitmap `assets/knob.png` (128×128, embedded via `spdsx_binary_data`; its indicator sits at exactly 0 radians / 3 o'clock, so the draw rotates by slider angle − π/2 — JUCE measures rotary angles clockwise from 12 o'clock), dimmed to 0.4 alpha when disabled. **The art is NOT centred in its canvas**: the circle's true centre is (63.5, 62.0), diameter 112 (measured from the alpha channel) — rotate about THAT point or the knob wobbles. A value ring arcs around the dial from the sweep start to the current angle, dark gray → white and thickening clockwise (segmented strokes; a segment's look follows its place in the full sweep). Also overrides `drawTickBox` (a ToggleButton with a radio group id draws as a circle-and-dot radio instead of V4's checkbox — the Dynamics pair) and `getSliderLayout` (a rotary with TextBoxBelow puts the box at the widget's LEFT edge and centres the dial over the box's span, so a knob's left alignment point IS the value box's left line — jdf's alignment rule; the old `translated(-kV4RotaryMargin)` nudges are gone). Applied by `PadSettingsPanel` (whole panel); owners declare the LnF BEFORE the widgets wearing it and clear it in their destructors.
- `kit_chooser.{h,cc}` — the header's unified kit control: prev/next arrows around a chip with kit number + name; clicking the chip drops the 200-kit menu, the pencil starts in-place rename. Pure view: callbacks out (`on_select`/`on_rename`), `SetCurrent` in, menu names via the `kit_name` provider (live model name for the active kit).
- `main_component.{h,cc}` — the grid, the KitChooser wiring (switching kits via DeviceDocument::SwitchKit), undo, File/Edit/View menus (via ApplicationCommandManager; `main.cc` must call `setApplicationCommandManagerToWatch` or menu enablement goes stale), MIDI in (ch 10 notes 60-68 -> velocity-aware `TriggerPad` through the layer mode; CC4 = hi-hat pedal), click/space anywhere in a pad = whole-pad hit through the layer mode with cursor HEIGHT in the pad as velocity (bottom=1, top=127; slot clicks route via on_click, pad-surface clicks via mouseDown), hits from any source flash the pad in a velocity colour (blue→amber→red, `VelocityColour` in sample_slot) and tint each sounding layer with its adjusted velocity while it plays, keys 1-9 trigger pads at a fixed velocity (kKeyVelocity = 100; the header VEL knob was removed 2026-07-27 — mouse clicks carry cursor height, MIDI its own), a green header transfer button ("↓ N samples") appears when the active kit references device waves not yet cached and downloads them on click (`UpdateTransferButton` from `UncachedDeviceWaveCount`), H key held = hi-hat pedal down (press = foot-close "chick": cuts the open layer, sounds the closed one; release silent; key-up detected via `keyStateChanged` + `isKeyCurrentlyDown` polling — `keyPressed` never reports releases), clicking a pad (tile, slot, or a digit key — not a MIDI hit) SELECTS it (`selected_`, an accent ring on its tile) and the left panel's Properties tab (`PropertiesTab`: heading + the `pad_settings` panel in a scrolling viewport) follows the selection, drag (move/copy one slot; ⌘ = whole pad; ⌥ = duplicate). Slot-level transport/space/click stays full-volume, ignoring layer mode.
- `pad_settings.{h,cc}` — the selected object's settings panel (hosted in the left panel's **Properties** tab; the per-pad "⋯" CallOutBox and the pad-header mode/fade widgets are gone since 2026-07-27): a gray title strip naming the object (`set_title`), then SECTIONS, each under its own full-width gray header band (Layer Type / Dynamics / Link Group / Layer Envelopes / Closed Pedal) — the panel fills the tab's width (`set_content_width` from the viewport) so bands span edge to edge, content left-aligns with the band text — Layer Type combo, the fade point/end KNOBS (shown per mode; the end knob's range floor tracks the point so >= holds structurally), a **Dynamics** section as a RADIO pair (Curve + its combo = dynamics on; Fixed Velocity + its knob = off — the active radio can't be clicked off, the dormant control greys out), Link Group, the Layer A/B mix knob triples, and on HI-HAT objects the "Closed Pedal" section (the panel grows and the hosting viewport scrolls). NO trigger-reserve control (deliberately dropped from the UI until loop/tempo support; the field still syncs). Pure view: `set_title`/`SetParams` in, `on_change` out with the FULL PadParams — the panel keeps a `params_` copy so uncontrolled fields ride through, and MainComponent applies `edited` wholesale as one "change pad N settings" transaction. `MainComponent::PadParamsChanged` refreshes the tab when the selected object changes underneath it, so undo/redo shows through live. JUCE gotcha (bitten 2026-07-12): a LinearBar's default `trackColourId` fill is indistinguishable from our dark background — tint per-value with `VelocityColour` if one ever returns.
- `sample_slot.{h,cc}` — a slot: spectrogram + info bar + transport buttons; drag source + FileDragAndDropTarget + DragAndDropTarget; hover highlight driven by parent (`on_drag_target`/`SetDragTarget`).
- **Window structure**: a GLOBAL BAR across the top (connection dot, `MainComponent::SetStatus` status text, the Sync button — visible on both tabs), then a `TabbedButtonBar` with two tabs: **Edit Kits** (the grid/browser UI, which is MainComponent's own children and painting, switched by visibility — `edit_tab_children_` is a ctor-end snapshot, `SelectTab` re-applies conditional visibility via `UpdatePadWidgets`/`UpdateTransferButton`) and **Bulk Edit** (`bulk_edit_panel`). Within Edit Kits a second bar (`surface_tabs_`) switches the editing SURFACE: **Pads** (3×3 grid, objects 0-8) or **Triggers** (2×4, objects 9-16) — one set of per-object widgets sized `kObjectCount`, `UpdatePadWidgets` folds the surface into visibility, `PadBounds`/`PadAt`/`SurfaceObject` are surface-aware, digit keys hit whatever surface shows (1-9 pads / 1-8 triggers), MIDI stays pads-only. View menu: Edit Kits ⌘1, Bulk Edit ⌘2. `keyPressed` passes ⌘-chords through (menu shortcuts) and ignores trigger keys off the edit tab; `mouseDown` likewise. The device tab's own `paint` is for EMPTY-STATE placeholders ("no device samples", "no matches") — never transient status, which a populated ListBox would cover.
- `device_samples.{h,cc}` — the left panel's "Device" tab (the panel is now a TabbedComponent: "Files" = sample_browser, "Device" = this): the wave pool as a ListBox (name + category per row) under a live case-insensitive substring filter box (matches wavename or filename); rows drag onto slots with description `spdsx-devsample:<index>` (`kDeviceSampleDragPrefix` in audio_files.h). Selection honors View > Autoplay exactly like the file browser and fires `on_preview` — a documented no-op until the sample cache delivers audio. Pool fills via **File > Load Device State** (the whole-document read; see Open items). **File > Download Kit Samples** (`MainComponent::DownloadKitSamples`) then pulls the ACTIVE kit's device waves into a local cache: on a worker thread `FindDevicePort` + per wave `ReadRemoteWave` (the f0 41 7a file read) + `RfwvToWav`, then handed back to the message thread (`OnWaveDownloaded`) which stores it as a DB blob (`DeviceDocument::StoreWaveAudio`); each cached wave refreshes its slots via `OnWaveCached`. A slot with a cached device wave loads and renders exactly like a local file (`LoadAudioIntoSlot`, shared with the file path); an uncached one shows name + duration + "on device" (`SetDeviceSample`). Device-tab autoplay previews a wave once cached. Both preloads and user imports are cacheable/playable (the device serves preload `.SMP` files over the file protocol even though the official app's UI won't export them); the Device tab just dims preloads as a factory/user cue.
- `sample_browser.{h,cc}` — left panel FileTree; drags onto slots; autoplay (View menu, persisted). Root folder AND tree state (open folders/scroll/selection, via TreeView openness XML in settings) persist across runs; restore re-applies on a timer until the async directory scans catch up (one shot can't reopen nested folders).
- `audio.{h,cc}` — AudioEngine (per-slot transports + a preview channel), miniaudio-free (pure JUCE).
- `spectro.{h,cc}` — renders spectrogram thumbnails via specgram (consumed through the vcpkg overlay port in `ports/specgram`, pinned to a `github.com/jdf/specgram` sha; bump REF there after pushing specgram).
- **FIRMWARE GATE**: `SpdsxDevice::kSupportedFirmware` is `"2.00"` — the only firmware any write path has been verified against. Every write op calls `RequireSupportedFirmware()` first (it queries `FirmwareField(0)` once and caches), so a new write op cannot quietly skip it; it throws, and both binaries surface that (spdutil's top-level catch, the app's worker catches). Reads and the focus-only DT1s (`SelectKit`/`SelectObject`, via the private `SendRaw`) are NOT gated — reading a strange unit is how you find out what it runs. `AssumeFirmware()` records a known version without a query: the test fixtures use it (otherwise every byte-exact write test would need a version reply queued first), and callers that already read the version can too. The app refuses in `SyncChangesWithDevice` up front, off its cached `device_firmware_`, and spdutil calls `RequireSupportedFirmware()` before the long bank reads in setmode/setlayer so it fails in a second rather than a minute.
- `device_ops.{h,cc}` — **the device operations spdutil runs** (JUCE-free, `device_ops_test.cc`): request structs, `PlanModeChanges` (the pure "which pads would change" core, shared with the Bulk Edit tab), the device-executing halves (`ops::SetMode`/`SetName`/`Info`), and `ops::CommandLine(request)`, which renders the equivalent spdutil invocation FROM the request — what lets the Bulk Edit tab promise the command it shows.
- `bulk_edit.{h,cc}` — **bulk edits applied to the DOCUMENT** (`bulk_edit_test.cc`): `bulk::PlanSetMode`/`ApplySetMode` over `std::vector<KitData>`, built on the same `PlanModeChanges` core, so the CLI (device-direct) and the tab (document-local) cannot drift. NOTE a default `KitData` is the FACTORY kit — pad 9 is HI-HAT, not MIX; test fixtures must normalize.
- `bulk_edit_panel.{h,cc}` — the **Bulk Edit tab**: left nav of operations (one per spdutil command), controls right, the spdutil-equivalent command line above Preview/Apply. **Applies to the document, never the device** — `BulkEditPanel::Handlers` carries `MainComponent::ApplyBulkSetMode`, which stashes the active kit, plans over all 200 `device_.kit(i)`, and performs a `bulk::SetModeAction` (an `UndoableAction` landing each touched kit via `DeviceDocument::ApplyBulkKit`; current only — base stays, so the kits read dirty and Sync pushes them) as ONE transaction named "layer mode change" in the CURRENT kit's undo history. **Undo/Redo menu items carry the transaction name** ("Undo layer mode change", "Undo move sample" — names are lowercase phrases), and kUndo/kRedo's perform refreshes MarkEdited/UpdateSyncButton because a bulk action edits kits no listener watches. Runs big text via a panel-local LookAndFeel. No connection needed, no progress bar (document edits are instant).
- `spdutil_args.{h,cc}` — **which flags each spdutil command accepts, and the `--kits` grammar** (JUCE-free, device-free, covered by `spdutil_args_test.cc`). spdutil parses every flag into one flat set of locals, so nothing structurally stops a flag meaningless to the chosen command from parsing cleanly and being dropped — that is how a one-pad sweep becomes a nine-pad one. `UnacceptedFlag` rejects any flag the command does not read and `TakesPositionalNumber` does the same for a bare number, both driven by the table here. **Which kits a write touches is always `--kits SPEC`** — comma-separated ranges, each one kit or `FIRST-LAST` (`108`, `108-200`, `1,5,10-20`; `1-200` is the only way to say "every kit"), parsed by `ParseKitSpec`. It is REQUIRED: `RequiresKitSpec` covers the six kit-writing commands, `TakesSingleKit` the four that write exactly one. `kit`/`selectkit`/`readwave`/`sendwave`/`deletewave` keep a positional number (a kit to read, or a sample index). When adding a command or flag to `spdutil_main.cc`, **add it to the table in `spdutil_args.cc` too** or it will be rejected at runtime.
- `device/` — SPD-SX PRO serial protocol (JUCE-free): `protocol` (DT1 message building, addresses, nibble codec, bulk-read requests + `SplitBulkImage`), `serial_port.h` (the `SerialPort` byte channel + `PortBackend` = what nodes might be the device and how to open one — both interfaces, NO platform named; `serial_port_macos.cc` is the one implementation, termios + IOSSIOSPEED + the /dev/cu.usbmodem* glob, all file-local behind `PlatformPorts()`, and CMake compiles it only on APPLE, failing at configure elsewhere), `spdsx_device` (frame wrap/unwrap + ops; **borrows** a `SerialPort*`, which is what lets a fake drive every op), `kit_image` (`CleanBulkImage` strips block framing; `ParseKits` reads the kit-record array), `sample_image` (`ParseSampleDir` reads the bank 0x20 wave-pool directory; `RemoteWavePath`, `ParseRfwvHeader`, `RfwvToWav`). `spdsx_device` ops now include: `DumpBank` (bulk read), `ReadRemoteWave` (the `f0 41 7a` channel-0x06 file read of a wave's `.SMP`, LIVE-verified), `WriteRemoteFile` (file write, LIVE-verified byte-exact — the upload write path), `DeleteWave` (LIVE-verified), and `Commit` (the `6a 03 21`/`22` flash handshake). Also `PcmToRfwv` (build a playable `.SMP` incl. the MD5 header checksum), `SetKitName`/`SetPadWave`/`SetPadLayerParams` (all kit-absolute, live-verified), and `UploadWave` (write+register). CLI write ops (all `--commit`-able; kit-writers require `--kits SPEC`): `assign --kits K --sample N --pad P.S`, `setname --kits K --name ...`, `setparams --kits K --pad P --params ...`, `sendwave <N> --from f.smp [--name X.wav]` (upload+register), `deletewave <N>`; reads `readwave`/`dump`/`kits`/`kit`/`samples`/`info`/`ping`. The GUI app links this lib too. The capture-derived byte-exact checks live in `source/device/*_test.cc` (they used to be `spdutil selftest`, which ran only when someone typed it; ctest and presubmit run them now).
- **Kit record layout, pad-param WRITE map, flash-commit handshake**: moved to `.claude/rules/device-protocol.md` (auto-loads when working under `source/device/`, `re/`, or the device-facing `source/` files).

## Unit tests & coverage (`testing/` + `source/*_test.cc`)
gtest suite (vcpkg `gtest`). **Convention: for every `source/foo.h` there is a `source/foo_test.cc`** holding that header's `TEST()`s, next to the code it covers. Each suite is its own TU, listed in the `spdsx_tests` target in CMakeLists.txt (add a line per new suite); it includes its header under test first, and keeps test-local helpers/fixtures in an anonymous namespace inside `namespace spdsx`. Suite names are global to the binary — keep them distinct. Test-only helpers live in `testing/` (`juce_test_environment.{h,cc}` = a gtest global env bringing up `juce::ScopedJuceInitialiser_GUI` for the session, registered so no suite has to; `temp_dir.h` = RAII temp dir for DeviceDb/DeviceDocument; `fake_serial_port.h` = a SerialPort that answers with queued replies and records writes; `fake_port_backend.h` = a PortBackend of fake nodes, some refusing to open). The `spdsx_tests` target is a JUCE console app compiling every production TU (minus the `main.cc`/`spdutil_main.cc` entry points) so most headers are testable; built by default. Run: `cmake --build --preset default --target spdsx_tests && ctest --test-dir build` (`gtest_discover_tests` registers each TEST as its own ctest entry, so `-R` filters per test; the binary also takes `--gtest_filter=` etc. directly). VS Code: the Testing panel lists each TEST with gutter run/debug via the **TestMate C++** extension (settings + CodeLLDB template in `.vscode/settings.json`); tasks `run tests`/`build tests`/`coverage report`/`presubmit`. **Tests are added one header at a time** (jdf's plan) — infra only so far, with a smoke test.
**Presubmit / push gate**: `./presubmit.sh` (repo root) builds everything + runs the suite, nonzero on failure. **`jj push-main` runs it and aborts the push if it fails** — jj runs NO git hooks, so the gate lives in jdf's global alias (`~/.config/jj/config.toml`), which runs `$(jj root)/presubmit.sh` when it exists and is executable (repos without one are unaffected; a fresh clone is gated with no setup since the alias is global and the script is tracked). `SKIP_PRESUBMIT=1 jj push-main` bypasses.
